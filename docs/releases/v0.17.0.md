# Quits OSS v0.17.0

Changes since the published v0.16.3 tag (`475ef900`), through `539275cc` (#466). This minor release covers 8 merged PRs in the self-hostable Quits core.

## Customers from the CVR register

- A customer created from a CVR lookup keeps the register's identity: its CVR number, legal name and registered address. Its address fields hold the billing address, which is the registered address unless one of its own is entered. Customers created by hand, foreign customers and every existing customer are unchanged (#463).
- On the new customer form and the customer page, the company name and CVR number of such a customer are read-only and follow the register. The contact person, email, phone, billing address, EAN/GLN and notes stay editable. A "Brug registreret adresse" switch shows the registered address, and turning it off lets you enter a billing address of your own (#464).
- "Opdater fra CVR" on the customer page refreshes the CVR number, legal name and registered address from the register for any customer with a valid Danish CVR number. A manual Danish customer becomes a register-backed one. A billing address that still equals the registered address moves with it; one of its own stays. The button appears only where the runtime has a CVR lookup (#464).
- When the register lists secondary names (binavne), the company name becomes a choice of the legal name or one of them, and invoices use the chosen name. A refresh keeps the chosen binavn while the register still lists it (#465).
- The customer picker creates a customer from a register match the same way. When the lookup fails while saving, the form and the picker show the lookup's message instead of a general error (#464, #466).
- The register's facts reach a customer only through the server's own lookup. An agent request cannot supply them (#463, #466).

## Tests

- Removed tests that only pinned markup, copy, wiring or what the types already guarantee, and shortened two slow tests (#459, #460, #461, #462).

## Upgrading

The workspace, app, contracts and shared package versions move together. Package manifests are the version authority. Apply the two new database migrations through the normal migration path before serving the updated app:

- `20261022200000_contact_registry_identity`
- `20261022210000_contact_registry_secondary_names`

Both only add columns to `contact`. The first adds the nullable `registrySource`, `registryCheckedAt`, `legalName`, `registeredAddress`, `registeredZip` and `registeredCity`. The second adds `registrySecondaryNames TEXT[]`, which defaults to an empty array. Existing rows need no backfill: they stay manual customers, and their address stays their billing address. There are no configuration changes.

- `contacts.create` accepts an optional `registryCvr`, eight digits. The server then looks the number up with the runtime's CVR lookup provider and takes the CVR number, legal name, secondary names and registered address from its answer. It fails with `NOT_IMPLEMENTED` when the runtime has no lookup and `NOT_FOUND` when the register has no such company. Without `registryCvr`, `contacts.create` behaves as before (#463, #465).
- New tRPC mutation `contacts.refreshFromCvr({ id })`, with the `contact:update` permission. It looks up the customer's stored CVR number and runs the new `contact.registry_refresh` command. It fails with `BAD_REQUEST` when the customer has no valid Danish CVR number (#463).
- `contacts.update` on a register-backed customer (`registrySource` is `"cvr"`) now refuses a different CVR number, or a company name other than the legal name or a stored secondary name, with a `BAD_REQUEST` validation error. Other fields, and all other customers, are unchanged (#463, #465).
- `cvrCompanySchema` in `@quits/contracts/cvr` gains an optional `secondaryNames` field, at most 20 names. A CVR lookup provider may now return it; providers that do not are unaffected. Releases before this one reject a lookup answer that includes it (#465).
- `createContactFromRegistry` and `refreshContactFromRegistry` are deliberately absent from `allCommands`, so an approved agent request cannot dispatch them. The `contact.create` command in `allCommands` no longer takes register facts, and a stored `contact.registry_refresh` request fails as an unknown command. The tRPC routes do the lookup themselves and are not affected (#466).
- `addressLines` now lives in `lib/contacts/registry.ts`, and is still exported from `components/onboarding-v2/lookup-preview.tsx` (#463). `cvrLookupError` is new; it lives in `lib/contacts/cvr-errors.ts` beside the new `cvrSaveLookupError` and is also exported from `routes/_app/contacts/-cvr-lookup.tsx` (#464, #466).

This release does not configure or deploy any hosted service.
