# Audit 4: event versioning, retention vs erasure (Codex, 2026-10-07)

## Versioning
- No schema version, no event-type union: DomainEvent.type String, payload Json (schema.prisma:576-594); PendingEvent accepts any string (services.ts:8-13). Writer/reader pass payloads through unchanged (events.ts:33-47, 74-84).
- Proposal: DomainEvent.schemaVersion Int @default(1) as a column (not payload); one registry type -> current version, EventType derived from its keys, appendEvents takes version from registry and rejects unregistered types; versioned payload contracts, any shape change bumps; pure upcastEvent helpers N -> N+1 that validate input and reject unknown future versions; schemaVersion in every activity response. Fallback: migration sets existing rows to 1; inventory existing shapes per type first.

## Retention vs erasure
- Contact deletion: blocked if any linked document (contacts.ts:200-228); unused contact physically deleted; contact.deleted event keeps the name.
- Organization deletion: Better Auth endpoint exists; Quits admin role lacks organization:delete so it is currently denied by access control, not policy (auth-config.ts:63-65, permissions.ts:71-81).
- Cascades that would destroy vouchers: Organization -> Invoice, CreditNote, Payment, DomainEvent, Contact, OrgSettings, OrganizationTaxId, Quote, RecurringInvoice, Agreement, AgreementTemplate, ApprovalRequest, AgentKey -> ApprovalRequest; Invoice -> InvoiceItem, InvoiceReminder; CreditNote -> CreditNoteItem; Agreement -> Deliverable (schema lines cited in full report). Job and CommandReceipt have no FK to organization.
- User deletion endpoint disabled (auth-config.ts:89-124); direct deletion cascades sessions/accounts/memberships only.
- PDFs: invoice PDF renders from live contact and org settings (invoice-pdf.tsx:217-229, 352-375); credit note prefers snapshots. No archived bytes. Database volume drop bypasses everything.
- Proposals: Contact.anonymizedAt + tombstone (clear name, email, phone, company, address, tax ids, notes; keep id, documents, snapshots, payments, events); Organization.closedAt + retentionUntil, soft close, purge only after 5 years past financial-year end and no holds; change the organization cascades above to Restrict, ApprovalRequest cascades to Restrict, child cascades (InvoiceItem, CreditNoteItem, InvoiceReminder, QuoteItem, Deliverable) to Restrict with explicit draft-child deletion; keep SetNull for Invoice->RecurringInvoice and Agreement->Template; optional User.anonymizedAt; minimize personal data in future event payloads; archive issued PDF bytes with checksum; self-hoster docs on backups and retention. Fallback: nulls on existing rows; unknown retention = purge prohibited; repair missing snapshots before anonymizing (invoice PDF must render from snapshot, buyer snapshot must include tax ids).
