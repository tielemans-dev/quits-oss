# Audit 3: payments, Stripe, FX, bad debt (Codex, 2026-10-07)

## Confirmed
- Partial payments work (settlement.ts:25-39). Manual overpayment rejected (payments.ts:123-145). Stripe overpayment stored, overpaidBy in event, balance clamped to 0, no customer credit (payments.ts:148-171).
- Payment.invoiceId mandatory; one transfer over several invoices = independent receipts, no parent (schema.prisma:504-527, contracts payments.ts:27-35). No unidentified/advance receipt possible.
- No refund path (manual or Stripe); negative payments rejected; refund webhooks not in allowlist (webhooks.ts:15-21). Void is local only, does not call Stripe (payments.ts:431-466).
- Credit note on a paid invoice leaves money owed back with no record (credit-pricing.ts:29-88).
- Stripe: amount_total gross, paidAt = webhook event time, session + intent ids; no charge, balance transaction, fee, net, payout, conversion (webhooks.ts:241-251, payments.ts:157-171). Multiple orgs may share one Stripe account (webhooks.ts:35-39), so payouts cannot be attributed from credentials alone.
- No base currency; no rate anywhere; manual payment has no currency field, copies invoice currency (payments.ts:107-111). EUR invoice paid in DKK cannot be represented.
- No write-off command. markPaid records a method=other payment (trpc invoices.ts:267-293), which would misrepresent bad debt. Reminders require open invoice + positive balance.

## Proposals
1. Receipt vs allocation: Payment = receipt (org, optional customer, account role, amount+currency, date, external id); PaymentAllocation(paymentId, invoiceId, amountInPaymentCurrency, amountInInvoiceCurrency); Refund linked to receipt. Events payment.received, payment.allocated, payment.allocation_reversed, payment.refunded. Invariants: allocations + refunds <= receipt; allocation <= outstanding. Postings: receipt Dr bank/clearing Cr unapplied; allocation Dr customer credit Cr debtor; refund Dr customer credit Cr bank. Wrong invoice = reverse allocation + reallocate. Crediting a paid invoice releases excess to customer credit. Legacy: one receipt + one allocation per nonvoided payment; excess over payable becomes customer credit after review.
2. Stripe clearing role per currency; persist charge id, balance transaction id, gross/fee/net with currencies, availability date, conversion. Events processor.fee_recorded, processor.currency_converted, processor.payout_settled. Fetch balance transaction async; unknown fee stays unknown, not zero; late fee = separate linked voucher. Legacy stripe receipts map to clearing, not bank.
3. Org accounting base currency; freeze at issue (both issue paths: no-email at invoices.ts:349-378 and delivery completion at document-delivery.ts:62-77) base currency, rate, direction, date, source, base amounts; freeze at receipt the actual amount/currency/account and valuation; allocation freezes invoice-currency discharged and base settlement value. realized FX = base settlement value - debtor carrying value discharged. Foreign-currency Stripe balance: realize debtor FX at receipt-date valuation, leave a foreign clearing asset. Legacy: base valuation unknown; never apply today's rate.
4. invoice.write_off: human-only (actor.kind=user check, own permission), outwardFacing=false, requires amount, effective date, reason, evidence. Event invoice.written_off with invoice- and base-currency amounts. paymentStatus stays truthful; new collection status written_off + amountWrittenOff; blocks checkout and reminders, expires sessions; recovery is an explicit event. Posting Dr bad debt Cr debtor gross; VAT component recorded separately with pending/eligible/ineligible assessment, never auto-reversed; eligibility approval produces a separate adjustment voucher. Legacy: never reinterpret credit notes as write-offs.
