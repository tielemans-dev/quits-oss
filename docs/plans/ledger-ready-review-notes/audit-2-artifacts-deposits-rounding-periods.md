# Audit 2: vouchers as files, deposits, rounding, closed periods (Codex, 2026-10-07)

## Files
- PDFs regenerated client-side per download (invoice-pdf.tsx:352, credit-note-pdf.tsx:199); no bytes or hash stored. Invoice PDF uses live settings and contact (invoice-pdf.tsx:224); credit note uses snapshots but live logo/phone. No quote PDF exists. Emails carry HTML + links (/pay, /q), no attachment; outbox keeps the sent HTML (outbox.ts:84). UBL rebuilt per export and reads current amountPaid (einvoice.ts:225, 157). No blob storage abstraction; RuntimeServices and bootstrap can take an override (services.ts:37, bootstrap.ts:16).
- Proposal: DocumentArtifactStore in lib/documents/artifact-store.ts injected via RuntimeServices; local-disk OSS impl; cloud R2/S3. Store bytes + metadata (document id, format, sha256, size, renderer version, created). Render from frozen issuance snapshot; store before emailing; publish refs on issuance in all three paths; serve archived bytes for issued docs; drafts regenerate; keep sent HTML; UBL at issuance or first authorized generation with provenance. Legacy: reconstruct once, label legacy_reconstructed.

## Deposits
- No prepayment line type, no deposit-invoice reference; positive quantities only (contracts invoices.ts:7). UBL PrepaidAmount uses amountPaid (ubl.ts:152). Agreements design treats deposit + balance = total, no deduction.
- Proposal: Invoice.invoicePurpose = sale | prepayment; DepositApplication(finalInvoiceId, depositInvoiceId, appliedNet, appliedTax, appliedGross, category, rate, receipt refs), immutable; fully paid deposits only at first; no reuse, currency/customer match. Example 25%: deposit 300/75/375; final services 1000/250 minus deposit 300/75 = 700/175/875. Keep deposit payments on the deposit invoice (never add to final amountPaid). Typed deduction rows, UBL allowances per category, no negative lines. Legacy: all sales; never infer prepayment.

## Rounding
- Per line, JS numbers, Math.round with EPSILON (compute.ts:8-76); totals sum rounded lines. Inclusive: round gross, net = gross/(1+rate) rounded, VAT remainder. One document rate assigned to all lines (pricing.ts:29). No discount fields. UBL groups by category/rate, decimal half-up, diff into payable rounding (ubl.ts:132). Verified: 3 x 0.03 at 25%: app VAT 0.03, UBL 0.02; 3 inclusive 0.01: app VAT 0.00, UBL 0.01; qty 3 at inclusive 0.01: stored unit x qty != line net.
- Proposal: decimal half-up VAT per category/rate total (matches Peppol), largest-remainder allocation to lines; discounts allocated proportionally across groups then lines before VAT; inclusive pricing preserves gross via explicit payable rounding. Freeze original decimal inputs, pricing mode, precision, calculationVersion, rounding mode, line amounts, discount allocation, VAT group bases/taxes, payable rounding. Legacy: calculationVersion = legacy per-line; expose UBL difference; never rewrite.

## Closed periods
- No period model. issueDate/supplyDate not exposed in invoice input; issuance uses command time (delivery completion uses attempt time). Payments accept past dates (payments.ts:234); void has no check. Recurring runs use run date.
- Proposal: OrgSettings.booksClosedThrough (inclusive, org timezone), lock settings row; one shared guard in issuance (all paths), credit note issuance, payment record and void; posting date separate from supply/receipt date; corrections issued in open period referencing original; late Stripe receipts preserved and flagged, never rejected; recurring runs crossing close pause with period_closed; reminders unaffected; closing refuses unresolved send attempts dated inside the period.
